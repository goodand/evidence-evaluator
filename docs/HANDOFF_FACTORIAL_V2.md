# Handoff retrieval factorial v2

## Purpose

This experiment answers two questions only:

1. Does a dynamic search controller improve zero-context handoff recovery over a fixed recall-first controller?
2. Does a retrieval-only helper improve the same recovery task?

It does not evaluate repository patch quality, general agent autonomy, safety policy, or non-Markdown evidence.

## Arms

| Arm | Helper | Main workflow |
|---|---|---|
| `S_STATIC` | none | fixed recall-first sequence |
| `S_DYNAMIC` | none | subject chooses the next allowed action |
| `R_STATIC` | retrieval-only | fixed recall-first sequence |
| `R_DYNAMIC` | retrieval-only | subject chooses the next allowed action |

The host owns candidates, reads, budgets, terminal decisions, and the trace. The main subject gets 10 retrieval actions plus one terminal action. The helper gets 4 actions and can return only candidate paths, read ranges, search trace, and uncertainty. Helper evidence is navigation only; the main subject must read every cited source itself.

Static is recall-first, not a deliberately weak baseline. It performs two queries, pool expansion, bounded reads, a graph walk, post-graph reads, and a terminal action. Dynamic uses the same action surface and budget but chooses the sequence. No-gold abstention requires both reformulation and graph walk.

## Cases and split

Development and held-out each contain exactly one case from eight strata:

- authority lexical overlap absent; graph needed
- reformulated query needed
- stale replica collision
- dated or same-basename collision
- authority in lexical candidate pool but outside lexical top 3
- multi-source reconstruction
- natural no-gold
- wrong-vault no-gold

The curator draft was generated by a fresh Codex process. Before freeze, the main materializer checked IDs, split balance, support ranges, unique mutation application, graph reachability, lexical-pool conditions, and private/public separation. It added deterministic Markdown navigation blocks where curator prose used non-executable arrows such as `A -> B`; this normalization occurred before any subject run and is recorded in the frozen corpus.

## Stages

Qualification is never included in arm estimates.

1. `screen`: 8 development cases x `S_STATIC/S_DYNAMIC` x 1 replicate = 16.
2. If dynamic improves at least two cases with no regression, no false absence, no premature stop, and at most one additional invalid run, run full held-out 2x2: 8 cases x 4 arms x 3 replicates = 96.
3. Otherwise hold the controller static and run held-out `S_STATIC/R_STATIC`: 8 cases x 2 arms x 3 replicates = 48. Interaction remains unmeasured.

## Commands

```bash
python3 -m evidence_evaluator.factorial qualify \
  --confirmatory-dir private_eval/handoff-confirmatory-v1 \
  --results-dir results

python3 -m evidence_evaluator.factorial freeze \
  --manifest private_eval/handoff-factorial-v2/manifest.json \
  --output private_eval/handoff-factorial-v2/freeze.json --verify

python3 -m evidence_evaluator.factorial canary \
  --manifest private_eval/handoff-factorial-v2/manifest.json \
  --freeze private_eval/handoff-factorial-v2/freeze.json \
  --case-id DEV-01 --arm S_DYNAMIC \
  --output results/handoff-factorial-v2-canary-DEV-01-S_DYNAMIC.json

python3 -m evidence_evaluator.factorial screen \
  --manifest private_eval/handoff-factorial-v2/manifest.json \
  --freeze private_eval/handoff-factorial-v2/freeze.json \
  --output-dir results/handoff-factorial-v2

python3 -m evidence_evaluator.factorial confirm \
  --manifest private_eval/handoff-factorial-v2/manifest.json \
  --freeze private_eval/handoff-factorial-v2/freeze.json \
  --output-dir results/handoff-factorial-v2
```

Every run is append-only. An existing helper, cell, or summary artifact causes the command to fail rather than overwrite it.

The screen additionally writes `screen-receipt.json`, which hashes every
screen cell and its summary. Before `confirm` or public `score` verification,
copy its `receipt_digest` into `TRUSTED_SCREEN_RECEIPT_DIGEST` in
`evidence_evaluator/factorial_pin.py` and commit that pin. Until this separate
authorization commit exists, confirm fails closed.

## Outcomes

The primary outcome is grounded continuation: valid runtime, all critical paths read, exact authority read, all claim ranges exposed, and correct state, next action, and stop condition. Positive-case recall and no-gold abstention are reported separately. Invalid runs remain in the intention-to-run denominator. Calls, retrieval actions, elapsed time, failure codes, and paired arm deltas are secondary outcomes.

MOCs, tags, backlinks, and symlink replicas are navigation surfaces, not authority. The experiment covers Markdown only; code, JSON, and `.mmd` evidence remain outside this result.
